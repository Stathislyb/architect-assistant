# Product scope

Architect Assistant helps architects turn development standards and architectural knowledge into useful instructions for developers' AI tools. The wider vision includes requirements, decision records, target architectures, and oversight across applications.

The first use case is developer instruction creation and maintenance. We compose three sources: a reusable development baseline, project concerns, and enterprise constraints. API documentation provides integration context; a separate policy determines whether an integration is permitted.

Architects own the source rules, applicability, exceptions, and evaluation criteria. Builders translate rules into focused instructions. Evaluators assess each candidate independently and provide evidence and feedback. Deterministic code controls composition, rendering, provenance, and the repair loop.

The local prototype accepts project profiles that adopt versioned packs from a researched development catalog and add approved local rules. It also accepts fully composed specifications for compatibility. Adoption is an authoring convention, not an authenticated approval system. Demonstration project and enterprise policies remain fictional.

Success means repeatable instruction structure, traceability to exact source revisions, separate verdicts for each criterion, bounded targeted repair, and safe updates when standards change. It does not mean identical model wording or guaranteed compliance by every coding tool.

The first runnable slice produces drafts and evaluation records. Actual coding-tool behavior tests, architect approval and publication, natural-language concern intake, and enterprise policy administration remain subsequent work.
